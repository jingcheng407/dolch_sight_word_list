# Design 1

## Requirements

用户反馈：在气泡探索功能中，点击"气泡探索"按钮后弹出的小圆圈（气泡）位置不正确。用户希望这些气泡显示在左边的空白区域，而不是当前的右侧位置。

具体需求：
1. 分析当前气泡探索游戏的布局结构
2. 识别气泡显示容器的CSS定位问题
3. 修改布局使气泡显示在页面左侧的空白区域
4. 确保在不同屏幕尺寸下都能正确显示
5. 保持气泡的交互功能和动画效果不变

涉及文件：
- `/dolch_games_demo.html` - 主要的游戏页面
- `/static/css/bubble-words.css` - 气泡样式定义
- `/static/css/ipad-layout.css` - 响应式布局
- 可能需要修改的其他布局相关CSS文件

## Solution

### 实施计划（TDD原则）

**阶段1：准备和备份（5分钟）**
1. 创建修改前的视觉基准截图（用于回归对比）
2. 备份当前CSS/JS文件
3. 验证测试环境可正常访问气泡探索功能

**阶段2：最小可验证修改（15分钟）**
1. 仅修改核心对齐问题：`.words-grid-bubbles`的`justify-content`
2. 立即测试验证左对齐效果
3. 如有问题立即回滚，确保功能正常

**阶段3：滚动行为优化（10分钟）**
1. 修改`focusBubble()`中的`scrollIntoView`参数
2. 测试点击滚动行为，确保无水平跳动
3. 在多个设备/浏览器中验证

**阶段4：聚焦态边界修复（15分钟）**
1. 修复聚焦态`padding`跳动问题
2. 测试聚焦/取消聚焦的左边界稳定性
3. 验证iPad响应式行为

**阶段5：增强和清理（10分钟）**
1. 添加`overflow-x`和`scrollbar-gutter`优化
2. 更新版本号，添加代码注释
3. 最终回归测试

### 具体技术实现

**根因分析**：
通过深入代码审查，发现问题的真正根因是：

1. **CSS对齐策略问题**：`.words-grid-bubbles`选择器在`static/css/bubble-words.css`中使用`justify-content: space-around`，导致气泡分散对齐而非左对齐
2. **滚动行为问题**：`focusBubble()`方法在`static/js/bubble-words.js`中使用`scrollIntoView({ inline: 'center' })`造成水平居中，给用户"右移感"
3. **溢出控制缺失**：仅设置`overflow-y: auto`，未限制`overflow-x`，可能引发横向滚动错觉

**最小改动解决方案**（推荐）：

**CSS修正** (`static/css/bubble-words.css`)：
```css
.words-grid-bubbles {
    justify-content: flex-start;  /* 替代space-around，实现左对齐 */
    overflow-x: hidden;          /* 防止横向滚动 */
    overscroll-behavior-x: contain; /* 改善滚动体验 */
    /* 可选增强：稳定滚动条 */
    scrollbar-gutter: stable;    /* 在支持的浏览器中减少滚动条显隐抖动 */
}

/* 可选：确保容器也左对齐 */
.bubble-words-container {
    align-items: flex-start;
}

/* 关键修复：聚焦态保持左边界不跳动 */
.bubble-words-container.bubble-focused .words-grid-bubbles {
    padding-left: 3px;          /* 保持与常态一致，避免左边界跳动 */
    padding-right: 10px;
    padding-top: 20px;
    padding-bottom: 20px;
    gap: 15px;
}

/* 移动端聚焦态同样保持左边界稳定 */
@media (max-width: 768px) {
    .bubble-words-container.bubble-focused .words-grid-bubbles {
        padding-left: 3px;      /* 保持与常态一致 */
        padding-right: 8px;
        padding-top: 15px;
        padding-bottom: 15px;
        gap: 12px;
    }
}
```

**JS滚动行为修正** (`static/js/bubble-words.js`)：
```javascript
// focusBubble()方法中的scrollIntoView修改为（推荐移除inline参数避免iOS兼容问题）：
targetBubble.scrollIntoView({ 
    behavior: 'smooth', 
    block: 'center'
    // 完全移除inline参数，避免iOS Safari水平位移风险
    // 如业务强需求必须水平居中，可择次选用 inline: 'nearest'，但需额外iOS验证
});
```

**iPad布局兼容性**：
- iPad布局中`.bubble-words-container`的`padding`由`var(--ipad-padding)`控制（覆盖`bubble-words.css`的`padding: 5px`）
- 聚焦态修改需确保与iPad的`--ipad-padding`值协调，保持左锚点不偏移
- 横/竖屏切换时验证`--ipad-padding`与聚焦态叠加后的视觉稳定性

**版本控制**：
- 更新`dolch_games_demo.html`中CSS版本：`bubble-words.css?v=7`（从v=6递增）
- 如有JS文件引用，同步递增版本号
- 测试时强制刷新缓存（Ctrl+Shift+R）

**验收标准澄清**：
- **左对齐定义**：首行第一个气泡与容器content box的左内边距对齐，实现紧凑贴左排列而非居中散开
- **交互不变**：点击放大、虚化、动画、语音均保持原样  
- **响应式要求**：iPad横/竖屏、移动端、桌面端均左对齐，无水平滚动条
- **滚动行为**：点击任意气泡仅垂直居中滚动，不发生水平位置跳动

## Tests

**聚焦测试方案**（针对根因修复）：

1. **布局/对齐测试**：
   - **初始渲染**：首行第一个气泡像素级靠左对齐（允许容器内边距），窗口缩放后仍保持靠左
   - **少量/单行用例**：确保气泡不会"居中散开"，而是紧凑贴左排列
   - **不同单词数量**：少于一行、正好一行、多行情况下均为左对齐，行内气泡不"散开"
   - **容器边界**：确认气泡与容器content box的左内边距对齐，无意外的右侧偏移
   - **聚焦态左边界稳定性**：点击进入聚焦/退出聚焦，观察首列气泡的左边缘像素是否保持一致（允许1-2px次像素差异）
   - **iPad覆盖验证**：切换横/竖屏验证`--ipad-padding`与聚焦态叠加后左锚点不偏移
   - **视觉基准**：截取修复前/后的对比图，验证首行左对齐像素差异

2. **交互/滚动行为测试**：
   - **垂直居中**：点击任意位置气泡后，目标气泡垂直居中显示
   - **水平位置保持**：点击后气泡整体保持靠左，无横向滚动条出现
   - **连续点击**：点击不同列的气泡，不出现水平"抖动/漂移"现象
   - **右边界测试**：连续点击靠右边界气泡，验证无水平回弹现象
   - **聚焦效果**：放大、虚化、动画效果正常，聚焦状态下仍保持左对齐

3. **设备/浏览器兼容性**：
   - **重点设备**：iPad OS Safari（横屏/竖屏）、iPhone Safari、Chrome/Firefox/Edge（桌面）
   - **滚动行为**：特别验证iOS Safari对`inline: 'nearest'`的支持情况
   - **CSS兼容性**：验证`overscroll-behavior-x: contain`在旧版浏览器中的降级

4. **回归测试**：
   - **其他游戏不受影响**：记忆游戏、拼写游戏、捕捉游戏、竞速游戏页面正常
   - **成就系统**：进度统计和成就解锁功能正常
   - **语音功能**：单词发音播放不受影响
   - **响应式布局**：其他页面的响应式行为未被破坏

5. **性能验证**：
   - **大规模测试**：≥120个气泡场景下的滚动流畅性，目标帧率≥30fps
   - **交互响应**：点击响应时间<200ms，动画过渡流畅度不下降
   - **内存占用**：修改后的CSS/JS不引入内存泄漏
   - **动画帧率**：气泡动画帧率保持稳定，无卡顿现象

**技术细节补充**：
- **CSS覆盖检查**：确认后续媒体查询无再次覆写`.words-grid-bubbles`的`justify-content`（当前仅调整gap/padding，无冲突），后续变更需同步评审此规则
- **代码注释**：在修改处添加注释标记"为何改为flex-start：左对齐需求"、"为何移除inline：避免iOS水平位移"、"为何聚焦态保持padding-left：避免左边界跳动"
- **滚动条优化**：`scrollbar-gutter: stable`在支持的浏览器中减少滚动条显隐抖动，不支持的环境下自动降级，不影响功能
- **关键发现**：聚焦态的`padding`变化（3px→20px/15px）会导致左边界跳动，必须保持`padding-left`一致性

**回滚方案**：
- **CSS回滚**：恢复`justify-content: space-around`
- **JS回滚**：恢复`inline: 'center'`参数  
- **版本回滚**：将CSS版本号还原为v=6
- **验证工具**：保存修改前的截图作为对比基准

**风险评估**：
- **风险极低**：仅修改对齐策略和滚动行为，不涉及核心交互逻辑
- **影响面小**：变更限制在气泡探索功能内，不影响其他模块  
- **易回滚**：所有修改均为参数调整，可在5分钟内快速恢复
