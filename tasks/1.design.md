# Design 1

## Requirements（修订版）

### 背景与目标
为现有儿童英语学习应用设计 iPad 优化方案，提升在平板设备（以横屏为主）的可用性与趣味性。在不改动后端接口与数据结构的前提下，通过前端布局与交互优化，实现“关键任务单屏完成、触控友好、视觉一致”的体验。

### 适配范围
- 设备：iPad（含 9.7/10.2/10.9/11/12.9 寸），横屏优先；竖屏提供功能等价但可能存在合理滚动的布局备用方案。
- 分辨率与像素密度：以逻辑像素布局，遵循安全区域（Safe Area），不依赖固定物理像素。
- 浏览器：Safari iPadOS 16+ 为主，Chromium 内核浏览器为辅。

### 核心需求（澄清后）
1. **单屏优先**：关键任务应在单屏内可完成（如：选择关卡→进入学习→完成小测→查看奖杯）。允许在单屏内使用分页/步进/折叠等方式组织较多内容，禁止全局性的长距离垂直滚动。
2. **iPad 优化**：充分利用横屏空间（≥1024x768 逻辑像素），网格与面板化布局优先，避免内容稀疏或拥挤。
3. **触控友好**：统一触控规格，保证儿童用户易点、易看、易理解。
4. **功能等价**：保留现有功能（学单词、玩游戏、小测试、我的奖杯），不删除、不弱化核心路径。
5. **风格一致**：延续卡通风格与动画基调，强化但不喧宾夺主，保证性能与可读性。

### 交互与视觉规范
- 触控目标：最小 44×44 pt；主要按钮≥48×48 pt；元素间最小触控间距≥8 pt。
- 字体与可读性：正文≥17 pt，标题≥22 pt；大文本对比度≥3:1，正文对比度≥4.5:1。
- 导航：顶部或侧边固定导航，图标+标签文案；返回/主页路径清晰，重要操作常驻可见。
- 布局：网格优先，避免密集信息墙；对超量内容使用分页器或分组折叠，不出现全页滚动条。
- 手势：单指点按为主；慎用复杂手势；允许有限的卡片区域横向滑动作为补充但需提供显式分页控件。
- 动画：60fps 目标；时长 150–300ms；可中断；避免大面积重绘与视差过度使用。

### 组件与页面要点
- 单词卡片网格：
  - 推荐 3–4 列 × 2–3 行（依据实际内容密度调优），保持卡片 3:4 或 1:1.2 纵横比；
  - 支持分页（页码/圆点+左右翻页），每页固定数量，保证单屏不溢出；
  - 状态：默认/选中/已学/锁定，状态可视且文案清晰。
- 弹窗/模态：
  - 宽度 60–80vw，高度不超过 70vh；内容多时内部可滚动，外层页面不滚动；
  - 移动端可退化为全屏模态；提供清晰关闭/返回；背景遮罩 40–60% 不透明度。
- 小测试：
  - 单题单屏或少量题目分步呈现；
  - 明确的进度指示、提交与重做入口。
- 奖杯页：
  - 网格化展示，支持筛选/分组；
  - 奖杯详情在侧栏或模态内展示，避免离开主列表。

### 技术约束（细化）
- 技术栈：沿用现有 HTML/CSS/JavaScript；允许引入轻量级 CSS 工具类或自研组件，不新增复杂框架。
- 后端：FastAPI 不变；接口契约不改；如需新增字段，采取后向兼容策略。
- 响应式：保留现有响应式能力；新增 iPad 横屏优先布局断点（如 ≥1024px）；小屏沿用原有滚动布局，无需强行单屏。
- 性能预算：首屏交互 < 2.5s（iPad 第八代基准），单页面脚本 < 300KB（未压缩前可适度放宽），动画流畅无明显掉帧。

### 成功/验收标准（可量化）
- 关键任务在 iPad 横屏下无需全页滚动即可完成；
- 触控命中率指标：所有可交互元素最小 44×44 pt；
- 网格/页面在 ≥1024×768 下不出现垂直滚动条；局部内容如题目列表可内部滚动或分页；
- 可读性：正文≥17 pt，标题≥22 pt，颜色对比符合 WCAG AA；
- 稳定性：主要用户流程通过手测回归（学习→测试→奖杯）；
- 性能：Lighthouse 性能评分≥80（近似），动画无明显卡顿。

### 非目标（明确边界）
- 不强制 iPhone 等小屏单屏化；
- 不重做课程内容与关卡体系；
- 不引入全新交互框架或重写后端；
- 不上线付费/账号体系改造。

### 风险与对策
- 文案长度/本地化溢出：使用自适应/截断+提示；提前做多语言长度审查。
- 数据量过大：采用分页/分组/虚拟列表，避免一次性渲染全部。
- 动画过度/性能风险：设定动画白名单与时长上限，必要时降级为淡入淡出。

### 开放问题
- 是否强制横屏（竖屏进入是否提示旋转）？
- 是否需要支持外接键盘与触控笔的辅助交互？
- 单词卡片的最大并发数量与分页策略是否有业务侧约束？

---

本修订将原"所有内容必须在一屏内显示，不允许出现滚动条"的刚性要求，调整为"关键任务单屏完成，允许在单屏内通过分页/折叠/局部滚动组织过量内容"，以避免信息拥挤与可达性下降，兼顾真实内容规模与儿童触控可用性。

## Solution

### 1. iPad横屏布局架构

#### 1.1 整体布局方案
采用**双栏布局**，充分利用iPad横屏空间：
- **左栏**：固定宽度320px，包含导航、进度条、快捷操作
- **右栏**：自适应宽度，主内容区域，单屏显示核心功能

```
┌─────────────────────────────────────────────────────────┐
│  Header: 快乐学单词 + 进度熊 (全宽)                        │
├──────────────┬────────────────────────────────────────────┤
│              │                                            │
│  左侧面板     │           主内容区域                        │
│  - 导航菜单   │        (单屏内容，无垂直滚动)                │
│  - 控制按钮   │                                            │
│  - 筛选选项   │                                            │
│              │                                            │
└──────────────┴────────────────────────────────────────────┘
```

#### 1.2 响应式断点策略
- **≥1024px (iPad横屏)**：双栏布局，单屏优先
- **768px-1023px (iPad竖屏)**：单栏布局，保留分页导航
- **<768px (手机)**：保持现有滚动布局

### 2. 单屏导航和内容组织方案

#### 2.1 导航重设计
将现有4个标签重组为左侧垂直导航：
```css
.nav-sidebar-ipad {
  width: 320px;
  display: flex;
  flex-direction: column;
  gap: 16px;
}
```

#### 2.2 内容区域分页策略
**单词学习模式**：
- 网格：3列×2行 = 6个单词/页
- 分页器：底部圆点导航 + 左右箭头
- 卡片尺寸：200×160px，触控友好

**练习模式**：
- 翻卡片：单卡片居中显示
- 导航：左侧面板显示进度和控制

**测试模式**：
- 单题单屏，大按钮选项
- 进度条顶部固定显示

### 3. 技术实现架构

#### 3.1 CSS架构优化
新增iPad专用样式文件：
```css
/* iPad横屏布局 */
@media (min-width: 1024px) and (orientation: landscape) {
  .container-ipad {
    display: grid;
    grid-template-columns: 320px 1fr;
    grid-template-rows: auto 1fr;
    height: 100vh;
    overflow: hidden;
  }
}
```

#### 3.2 分页组件实现
创建可复用的分页组件：
```javascript
class PaginationController {
  constructor(items, itemsPerPage = 6) {
    this.items = items;
    this.itemsPerPage = itemsPerPage;
    this.currentPage = 0;
  }
  
  getCurrentPageItems() {
    const start = this.currentPage * this.itemsPerPage;
    return this.items.slice(start, start + this.itemsPerPage);
  }
}
```

#### 3.3 触控优化
- 最小触控目标：44×44pt
- 主要按钮：48×48pt以上
- 间距：最小8pt
- 字体：正文≥17pt，标题≥22pt

### 4. 兼容性保障

#### 4.1 渐进式增强
- 基础功能：现有滚动布局
- 增强功能：iPad单屏布局
- 降级策略：检测屏幕尺寸自动切换

#### 4.2 JavaScript适配
```javascript
class ResponsiveLayoutManager {
  constructor() {
    this.isIPadLandscape = window.matchMedia(
      '(min-width: 1024px) and (orientation: landscape)'
    ).matches;
    
    this.setupLayout();
  }
  
  setupLayout() {
    if (this.isIPadLandscape) {
      this.enableSingleScreenMode();
    } else {
      this.enableScrollMode();
    }
  }
}
```

## Tests

### 1. 单元测试
```javascript
describe('PaginationController', () => {
  test('should return correct page items', () => {
    const controller = new PaginationController([1,2,3,4,5,6,7,8], 6);
    expect(controller.getCurrentPageItems()).toEqual([1,2,3,4,5,6]);
    
    controller.nextPage();
    expect(controller.getCurrentPageItems()).toEqual([7,8]);
  });
});

describe('ResponsiveLayoutManager', () => {
  test('should detect iPad landscape mode', () => {
    // Mock window.matchMedia for iPad landscape
    Object.defineProperty(window, 'matchMedia', {
      value: jest.fn(() => ({ matches: true }))
    });
    
    const manager = new ResponsiveLayoutManager();
    expect(manager.isIPadLandscape).toBe(true);
  });
});
```

### 5. 性能测试
```javascript
describe('Performance Tests', () => {
  test('page load time under 2.5s on iPad', async () => {
    const start = Date.now();
    await page.goto('/', { waitUntil: 'networkidle2' });
    const loadTime = Date.now() - start;
    
    expect(loadTime).toBeLessThan(2500);
  });
  
  test('animation runs at 60fps', async () => {
    // 监测CSS动画帧率
    const fps = await page.evaluate(() => {
      return new Promise(resolve => {
        let frames = 0;
        const start = performance.now();
        
        function countFrames() {
          frames++;
          if (performance.now() - start < 1000) {
            requestAnimationFrame(countFrames);
          } else {
            resolve(frames);
          }
        }
        
        requestAnimationFrame(countFrames);
      });
    });
    
    expect(fps).toBeGreaterThanOrEqual(55); // 允许5帧误差
  });
});
```
