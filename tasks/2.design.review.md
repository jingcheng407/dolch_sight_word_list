# Design 2 评审与修改建议

本文对 `tasks/2.design.md` 进行可行性评审，并给出面向落地的修改建议与代码片段，帮助快速推进“字体与可读性优化”。

## 概览

- 优点：问题定位完整（字体加载、对比度、跨设备差异），强调 WCAG/TDD/渐进增强与分阶段发布，方向正确。
- 待改进：少量实现细节不可行或脆弱（外链字体写法、环境光检测、性能指标过于理想化），测试断言过于耦合具体颜色值，建议改为对比度断言。

## 关键风险/阻塞

1. 外部字体加载示例不正确：`@font-face src` 不能指向 Google Fonts 的 CSS URL。需改为自托管 `.woff2` 或用 `<link ...fonts.googleapis.com...>` 引入。
2. “环境光线条件”检测不可行：iOS/Safari 无 Ambient Light Sensor 支持，应改为“手动室内/室外模式切换”。
3. 性能指标“字体加载 < 500ms”在弱网不现实，建议转为“零 FOIT、可接受 FOUT、文本可读时间”一类体验型指标。

## 可行性与范围判断

- CSS 变量重构对比度：低风险、收益高，适合先行。
- JS 智能对比度在渐变/图片背景下成本高、不稳定；建议以设计约束（遮罩/面板）为主，JS 仅兜底。
- `clamp()` 在 Safari 14+ 可用，保留作为主要方案，提供基础 fallback 即可。
- 与 iPad 适配需统一排版度量（字号、行距、对比）以避免冲突。

## 具体修改建议

### 1) 字体加载与回退（两种可选方案）

- 方案A：继续使用 Google Fonts（最少改动）

```html
<!-- 优先预连接字形域名，降低握手开销 -->
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Fredoka:wght@400&display=swap" rel="stylesheet">
```

- 方案B：自托管字体（可控性更强，离线稳定）

```html
<!-- 预加载字体，避免首屏阻塞布局但允许 FOUT -->
<link rel="preload" as="font" href="/static/fonts/fredoka-400.woff2" type="font/woff2" crossorigin>
```

```css
/* 自托管字体，并使用 metrics override 降低 CLS */
@font-face {
  font-family: 'Fredoka';
  src: local('Fredoka Regular'), url('/static/fonts/fredoka-400.woff2') format('woff2');
  font-weight: 400;
  font-style: normal;
  font-display: swap; /* 弱网建议 optional；桌面或好网可用 swap */
  /* 调整回退字体度量，减少切换位移 */
  ascent-override: 92%;
  descent-override: 24%;
  line-gap-override: 0%;
  size-adjust: 102%;
}

:root {
  --app-font-stack: 'Fredoka', -apple-system, BlinkMacSystemFont, 'SF Pro Text',
    'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', system-ui, sans-serif;
}

body { font-family: var(--app-font-stack); }
```

- 策略建议：
  - 移动弱网可用 `font-display: optional`，减少迟到切换；其它场景 `swap`。
  - 仅引入 1 个字重，避免超过“字体总资源 ≤ 200KB”的约束。

### 2) 渲染与清晰度

- 不要全局启用 `text-rendering: optimizeSpeed`、`-webkit-font-smoothing` 等，它们跨浏览器效果不一致，可能导致发虚。
- 避免正文使用 `text-shadow` 以“提高清晰度”，仅在标题/装饰性元素酌情使用。
- 建议排版基线：

```css
:root {
  --font-size-body: clamp(17px, 1.6vw, 18px);
  --font-size-h1: clamp(22px, 2.8vw, 28px);
  --font-size-button: clamp(16px, 1.6vw, 18px);
}

body { font-size: var(--font-size-body); line-height: 1.5; }
.h1, h1 { font-size: var(--font-size-h1); line-height: 1.25; }
button, .btn { font-size: var(--font-size-button); }
```

### 3) 对比度与色彩

- 建议提供“品牌色 → 文本安全色”的映射表，仅在合适背景上使用品牌色文本；复杂背景统一加遮罩或使用纯色面板承载文本。

```css
:root {
  /* 原品牌色（用于背景/装饰） */
  --primary: #ff6b6b; --secondary: #4ecdc4; --accent: #ffe66d;
  /* 文本安全色（AA 合规） */
  --text-primary: #d63031;  /* 替代原红 */
  --text-secondary: #00b894; /* 替代原青 */
  --text-accent: #fdcb6e;    /* 替代原黄 */
  --text-dark: #2d3436;      /* AAA */
  --text-medium: #636e72;    /* 加深后的中灰 */
}

.word-text { color: var(--text-dark); }
.word-text.is-primary { color: var(--text-primary); }
.word-category { color: var(--text-medium); }

/* 高对比度与无障碍支持 */
@media (prefers-contrast: more) { :root { --text-primary: #b71c1c; } }
@media (forced-colors: active) { .word-text { forced-color-adjust: none; } }
@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }
```

- 复杂背景规则：文本所在容器一律加半透明遮罩（40–60%）或使用纯色面板，禁止“白字直接压图”。

### 4) 响应式字体系统

- 保留 `clamp()`；旧环境 fallback 到固定字号即可。
- 在 iPad 横屏主断点（≥1024px）可适度放大标题与按钮尺寸，确保可触目标≥44×44pt。

### 5) 测试策略调整

- 对比度测试：实现真实 WCAG 计算（sRGB 线性化 → 相对亮度 → ratio），断言“≥4.5:1”，避免断言具体 `rgb(...)`。
- 视觉回归：为测试环境统一使用自托管测试字体，降低跨平台差异；避免将字体加载不确定性带入快照。
- 字体 API：`document.fonts` 不可用时走兜底路径（当前设计已考虑）。

### 6) 性能与指标（体验导向）

- FOIT = 0（`swap`/`optional` 策略）；允许轻微 FOUT。
- 首屏“文本可读时间”≤ 2s（弱网用回退字体达成）。
- 字体切换导致的 CLS ≤ 0.02（配合 metrics override）。
- 监控项：所用字体策略、FOUT 发生次数、回退占比，而非仅耗时。

### 7) 文件与集成

- 建议合并 `contrast-optimizer.css` 与 `text-rendering.css` 为 `static/css/typography.css`，减少样式碎片；iPad 专属规则放入 `ipad.css` 对应断点。

```html
<!-- CSS 引入顺序：基础样式 → 排版/对比度 → 设备定制 -->
<link rel="stylesheet" href="/static/css/style.css">
<link rel="stylesheet" href="/static/css/typography.css?v=1">
<link rel="stylesheet" href="/static/css/ipad.css">

<!-- 字体与对比度增强脚本置于初始化前，使用 defer -->
<script src="/static/js/font-loader.js?v=1" defer></script>
<script src="/static/js/contrast-optimizer.js?v=1" defer></script>
```

## 拟定修改片段（可直接替换/采纳）

- Google Fonts 正确用法与自托管示例：见“字体加载与回退”。
- 移除全局 `text-rendering` 与正文 `text-shadow` 的建议，改为统一的排版基线与无障碍媒体查询。
- 对比度变量与类命名示例：见“对比度与色彩”。

## 建议更新验收标准

- 文本在目标设备上“始终可读”（AA 对比度，字号≥正文 17px）。
- 零 FOIT；弱网允许 FOUT；CLS ≤ 0.02。
- 复杂背景文本统一加遮罩或面板承载，无局部不可读。

## 开放问题（需产品/设计确认）

- 字体来源偏好：是否允许使用 Google CDN？如受限则改自托管。
- 品牌色向“文本安全色”的允许偏移幅度（明度/饱和度/色相）。
- 是否统一在图片/渐变背景上加遮罩（更易落地但有视觉取舍）。
- 是否接受使用 font metrics override（现代特性）以换取更低 CLS？
- 视觉回归测试是否落地到本仓库（引入 Node 工具链），或先走手测流程？
